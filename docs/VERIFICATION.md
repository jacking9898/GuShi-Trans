## 验证边界

自动化无界面浏览器不能点击 Chrome 的原生可选权限授权弹窗，因此浏览器测试使用**临时 manifest** 预授予唯一的 localhost 模拟接口权限；扩展运行时代码逐字节复用源文件，发布 manifest 不包含该预授权。正常安装后的原生授权弹窗应由用户保存设置时确认。Node 逻辑测试另行覆盖了未授权时禁止请求的分支。

未使用真实用户密钥，也未调用真实 DeepSeek 或其他付费模型。真实服务可用性、生成内容的准确度、系统语音发声及多音字发音，需在用户本机配置后检查。没有进行 Chrome 应用商店发布。

可复现命令及依赖安装见项目 README。界面截图位于 `test-results/`，不包含真实密钥或私人页面。

## v1.0.2 思考开关、输出限制与原生侧栏

日期：2026-11-17，沿用上述环境。

- 31 项逻辑测试全部通过。覆盖 DeepSeek 官方接口默认显式关闭思考、开启后的输出预算与等待策略、两个设置开关的保存、思考参数的缓存隔离，以及普通兼容接口不携带 DeepSeek 专属字段。
- 流式及非流式响应均测试了两种输出上限情况：只有思考而没有正文时，提示关闭深度思考重试；已返回可解析 JSON 时保留译注，显示内容可能不完整的提示。思考原文不会显示或导出，不自动发起额外请求。
- 实际扩展点击划词工具后成功调用 Chrome `sidePanel.open`，原生侧栏页面完成一次真实 HTTP 模拟接口查询。打开侧栏失败时不派发查询，防止回退浮窗时重复请求。
- 使用同一侧栏页面在测试标签页验证加载已有结果、手动重新生成、生成中 / 完成后反复切换模式、滚动、字号及错误提示。切换模式不增加请求或连接中断。
- 将测试网页视口设为 800 像素，模拟侧栏打开后网页变窄的情况，新选文仍进入已打开侧栏；调用 Chrome 原生关闭 API 后，再次划词回退到窄屏浮窗，成功结果继续复用。
- 原有划词、收藏、导出、重试、取消、恶意 HTML、安全错误信息和多尺寸页面回归通过。新增 `thinking-switch.png` 与 `reading-sidepanel.png` 界面截图。

验证边界：无界面 Chrome 不显示浏览器自身的侧栏边框，因此没有对正常 Chrome 窗口中的原生分隔线位置或网页自动缩窄后的像素布局做可视截图验证。侧栏页面截图来自相同页面在测试标签中的渲染；原生侧栏的默认位置遵循 Chrome 设置。没有使用真实 DeepSeek 密钥调用付费模型。

协议依据：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[Chrome Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)。

- 42 项逻辑测试通过。覆盖旧配置完整迁移、多配置校验、空密钥草稿、公开元数据脱敏、按配置选择接口 / 模型 / 密钥、缓存隔离、权限撤销后禁止使用缓存、请求生成中切换时保留原始来源、删除单套密钥，以及侧栏交接保留明确选择的配置。
- 对 DeepSeek、OpenAI、通义千问三个官方预设分别验证请求 URL、模型、Authorization 和参数。DeepSeek 默认显式关闭思考；通义千问支持的混合思考模型默认显式 `enable_thinking=false`，开启时只发送千问参数；OpenAI 非推理预设不携带其他服务的思考参数。
- 浏览器通过实际设置页面添加、保存、切换和刷新多套配置，逐一核对各自的假密钥及模型；删除一套密钥不影响其他配置。配置全部移除后仍可保存、刷新、显示引导并重新添加无密钥草稿。

- 原有三个阅读模式的本地切换、会话缓存、取消、重试、收藏、导出、恶意 HTML、安全错误提示、严格 CSP 和 320 / 768 / 1024 / 1440 像素布局回归通过。新增设置截图 `multiple-providers.png`。

验证边界：浏览器里的三套配置都改用本地模拟服务和假密钥，未对真实付费服务作连通性或生成质量验证。官方预设和专属参数由独立请求测试验证，浏览器自身的权限弹窗和侧栏边框限制同上。

协议依据：[OpenAI GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini)、[百炼 OpenAI 兼容接口](https://help.aliyun.com/en/model-studio/qwen-api-via-openai-chat-completions)、[千问思考模式](https://platform.qianwenai.com/docs/developer-guides/text-generation/thinking)。

## v1.0.5 OpenAI 兼容

- 48 项逻辑测试通过。新增 GPT-6 Luna 回归模拟：服务端拒绝旧 `max_tokens`，新请求使用 `max_completion_tokens`，关闭 / 开启思考分别发送 `reasoning_effort=none/medium`，每次查询仅调用一次。GPT-4.1 mini、未知模型和自定义网关不猜测思考档位。
- 参数错误分别测试 `max_tokens`、`max_completion_tokens`、`reasoning_effort`、`response_format` 和 `model`；不把错误原文、任意参数名或密钥反射到 UI。另覆盖模型无权限、额度不足和超大错误响应体的限长 / 取消。
- 浏览器实际 HTTP 400 模拟返回被拒绝的参数，设置页显示相应诊断，忽略含假密钥的原始 message，不自动重试。原有多 Provider、模式切换、划词 / 侧栏及多尺寸回归通过。

验证边界：没有读取用户密钥或重放用户的付费请求；尚未取得截图中那次 HTTP 400 的服务端原始错误字段。修复针对代码中确认存在的 OpenAI 参数适配遗漏，真实服务连通性须由更新后再次测试连接确认。
